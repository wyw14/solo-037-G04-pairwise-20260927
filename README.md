# WaveLab

WaveLab is a local HTTP service for tow-tank experiments. The original equipment and interlock pages expose a fixed commissioning diagnostic scenario. Operator measurements are a separate live data path.

Set `WAVELAB_DATA_DIR` to choose the archive directory (default `data/wavelab`). `POST /api/measured-runs` accepts `name`, `model_name`, `section`, and `carriage`. `POST /api/measured-runs/{id}/evidence` accepts `kind` (`wave_time`, `force`, or `speed`), `source_id`, finite `value`, and `recorded_at` in RFC3339 form. `GET /api/measured-runs`, `GET /api/measured-runs/{id}`, and `GET /api/measured-runs/{id}/analysis` return the supplied records and wave/force summary. Measurements are committed to `operator-measurements.json` before they are published in memory, and are reloaded when the service restarts. The archive does not automatically grant a safety permit or drive hardware.

`GET /api/measured-runs/{id}/resistance` derives the resistance-versus-speed curve of a run from its `speed` and `force` frames. Frames are paired inside fixed time windows (`window_ms`, default 1000, clamped to 50–60000); abnormal frames are rejected (non-finite values, non-positive speeds, and within-window MAD outliers beyond `outlier_sigma`, default 3.5). Windows lacking either channel are dropped and reported under `dropped_windows`; fully empty grid slots are counted in `empty_windows`. Each curve point reports the window bounds, speed/force means with frame counts, a 95% uncertainty interval on the force mean (`force_lower`/`force_upper`), and the contributing evidence IDs, so every point traces back to the archived frames. Points are ordered by speed.

The `internal/probe`, `internal/force`, `internal/permit`, `internal/carriage`, `internal/track`, `internal/wave`, `internal/absorber`, and `internal/journal` packages provide component logic for further work. Their diagnostic use does not imply that the original HTTP pages accept real sensor streams.
